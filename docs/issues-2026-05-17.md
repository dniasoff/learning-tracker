# Issues — 2026-05-17

Captured from product review session. Ordered as raised; not yet prioritised.

---

## I-1 — Track card: split current-session progress from lifetime curriculum progress

**Screen:** Dashboard → active track card
**Observed:** Single "Lifetime learning • 0.00%" line.
**Required:** Two separate values —
- Current session progress (completions since last `activatedAt`)
- Lifetime curriculum progress (all completions ever for this curriculum)

---

## I-2 — Rename and clarify "Completions" vs "Tasks Done"

**Screen:** Progress overview
**Observed:** Two tiles labelled "COMPLETIONS" and "TASKS DONE" — meaning is ambiguous.
**Required:**
- **Items Learned** — distinct curriculum units finished through tracks (idempotent: completing the same unit again doesn't increment). Maps to unique `sefariaRef` completions via tracks only.
- **Tasks Done** — total task events logged through tracks (accumulates; chazara counts again).
- Both scoped to **track activity only** — bulk-marked lifetime items are excluded.
- Naming must be curriculum-agnostic (works for Bavli, Mishnayos, Mishna Berurah, etc.).

---

## I-3 — Rich "Items Learned" breakdown + separate Lifetime view

Two distinct views required:

### Track breakdown (Items Learned)
- Scoped to tasks done through tracks only.
- Per curriculum, drills into the curriculum's natural hierarchy:
  - Talmud Bavli: Seder → Masechta → Daf
  - Mishnayos: Seder → Masechta → Perek
  - Mishna Berurah: Chelek → Siman
  - (other curricula: equivalent hierarchy)
- Presentation should be motivational — visual sense of coverage and progress.

### Lifetime view (separate location in app)
- Same layout and controls as the track breakdown.
- Includes everything: track completions + bulk-marked lifetime items.
- Full picture of all material ever covered, regardless of how it was recorded.

---

## I-4 — Curriculum overlap: Tenach ⊇ Chumash + Nach

**Problem:** Tenach, Chumash, and Nach are overlapping curricula. An item learned through a Chumash track is also a Tenach item.
**Required:** The Items Learned breakdown and Lifetime view must:
- Not double-count items that belong to multiple curricula.
- Correctly reflect coverage wherever a unit belongs in the hierarchy (e.g. a Bereishit perek counts toward both Chumash and Tenach).

---

## I-5 — Two-way cross-device sync

**Required:** Installing the app on a second device must produce identical state on both. Changes made on either device must propagate to the other reliably. Users must be able to switch devices freely without data loss or inconsistency.

---

## I-6 — App-wide sluggishness (performance regression)

**Observed:** Button presses and screen navigation take several seconds throughout the app. This is a regression — the app was faster before the sync engine rebuild (DNI-333/334/335).
**Scope:** Affects all screens, not isolated to one area.
**Debugging:** Device available via ADB for profiling.

## Design decisions also captured this session

### Delete / restore behaviour (not yet implemented)

| Action | Completions | Track row |
|---|---|---|
| Soft delete (`deleteTrackAndData`) | Preserved forever | Tombstoned (`deletedAt` stamped) |
| Restore (`restoreOrCreate`) | Preserved — carry forward into lifetime stats | Reactivated; `activatedAt` reset to now (fresh learning session) |
| Hard delete / purge (`purgeHistory`) | Physically deleted | Physically deleted (no tombstone) |

**Current code differs:** `restoreOrCreate` currently purges completions on restore (R3 fix) and preserves `activatedAt` (R4 fix). Both need reversing to match the above design. Tests for N4, N5, and lifecycle group B/D need updating accordingly.

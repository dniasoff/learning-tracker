## 1. Executive brief

**Thesis.** The suite's problem is verification placement, not volume: ~10,370 green tests while ~931 fix commits shipped and on-device run 6 alone found 22 defects the suite caught **zero** of. The defects live on five seams the suite never crosses — device lifecycle (~60% of escapes), weak/friendly fixtures (the three P0 lifetime-corruption escapes e22fb126/bf92cde9/98d5e64b), missing reactivity contracts (63 provider-staleness escapes), over-stubbed screen tests (73% zero-interaction), and a coverage gate that measures volume not risk (123 files invisible to lcov; merge router at 0%). This plan does NOT chase the headline percentage. It builds the small set of high-leverage artifacts that sit ON those seams, then hardens the gates so the seams stay covered, then opens the device lane the host suite structurally cannot replace.

**Shape.** Six waves. T0 is five NEW-file signature artifacts (collision/property fixtures + read-time migration assertions, the provider-reactivity contract, merge-router value-binding + malformed-payload codecs, live en+he goldens, `make ci` format parity) — additive, zero contention with the standards merge trains, executable in one sitting, and each item pays independently the moment it merges. T0G (grafted per judge mandate) immediately follows T0: the parent-PIN AutoRoute-guard device journey runs as an early manual gate on @5556, because PIN-bypass/lockout is a named next-P0 class and its true seam (the b8464ccc push-result completer) is unreachable from the host suite — it does not wait for the fourth wave. T1 replaces the flat 60% coverage floor with an every-file-in-lcov check plus risk-tiered floors, adds burn-in/quarantine flake policy, and harvests the stranded AUD-firebase-04 fix before any worktree cleanup. T2 converts 3 canonical screens to real-seam tests with an en+he harness (deliberately tiny — wave 4 owns the other 426 files). T3 completes the device e2e lane (lane harness, Hebrew smoke, per-entity sync round-trip). T4 closes the parked register items nothing else will fix and gates the Play-Store deploy on green CI.

**What changes by when.** After T0+T0G (target: day 1–2): the recurring P0 corruption class, the 63-escape staleness class, the wrong-merger corruption class, and the PIN-lockout class each have a test that provably fails on regression; goldens are live in en+he. After T1 (day 3–4): CI is risk-measuring — no file can hide from coverage, critical sync/auth/database dirs carry ≥85% floors, flaky changes burn in 20×. After T2–T3 (week 2): canonical screens assert real domain content in both directions, and the device lane covers the four seams widget tests cannot reach. After T4: parked holes closed, production deploys blocked without green CI.

**Delivery model.** Each wave dispatched as a Workflow fix-engine: sonnet builders in isolated git worktrees → opus adversarial reviewers (bounce cap 3) → serialized merges onto `tea-fix/2026-07-09`. Wave exit gate everywhere: `cd learning_tracker && make ci` green (~6.5 min) plus wave-specific runnable checks. Human review at wave boundaries only.

**Universal new-gate rule.** Every new quality gate ships with a proven red demonstration — introduce the defect class, watch the gate fire, revert — captured in the item's acceptance. Gates without a demonstrated red are decorative and do not merge.

**(c) Provider-reactivity contract (TEA-004).** ONE table-driven harness with a `const derivedProviderRegistry` of `{provider, upstreamMutation}` entries; per entry it spins a `ProviderContainer`, reads the initial value, applies the upstream mutation (bump `completionCommittedProvider` tick / invalidate source), pumps, and asserts re-emit. **(d) Fixture overhaul (TEA-002/007).** Three parts. (1) Shared `collision_fixtures.dart`: two curricula sharing BARE level2/3/4 ids (Bereishis/Shemos perek 1; Berakhos/Shabbos daf 2). **(e) Coverage-gate redesign (TEA-013).** Two parts in `tool/coverage_gate.dart`. (1) Every `lib/**.dart` absent from `lcov.info` HARD-FAILS unless on a tiny, visible, ticketed allowlist of genuinely un-instrumentable files (abstract gateways) — closing the 123-file denominator hole; the allowlist hides nothing, each entry carries a follow-up. Floors are set from MEASURED post-T0 numbers, which is why T1 lands after T0.

**(f) Flake policy (TEA-038/036/016).** Burn-in: a CI job runs changed `*_test.dart` vs merge-base 20× with `--test-randomize-ordering-seed random`; any failure is red. Quarantine: a skip citing a live bug MUST use `@Tags(['quarantine'])` + a `DNI-####` ticket and is tracked as an expected-failure, never silently disabled; an audit grep rejects DNI-less skips (extends AG-6). Bare `pumpAndSettle()` with no bounded timeout is audit-rejected (warn→enforce). Auto-retry-on-fail is REJECTED — it masks flakes.

**(g) Non-goals (explicit).** (1) NOT rewriting the 429 over-stubbed feature tests wholesale — wave 4 owns per-file TQ-8; T2 touches only 3 canonical screens. (2) NOT chasing the headline coverage percentage. (3) NOT adopting patrol/native automation. (4) NOT re-running the two missing audit dimensions (acceptance-journeys, e2e-reality) inside this plan — a separate recon is recommended before large acceptance-journey investment. **[Amendment 1: DISCHARGED]** This recon was since delivered as the [audit supplement](../test-reviews/tea-audit-2026-07-09/_TEA-AUDIT-SUPPLEMENT-1.md) (13 confirmed findings); its rulings are folded into §§4–11 and Amendment 1, and human decision point 5 can now be ruled on with that evidence. ## 9. Sequencing rationale

T0 is all NEW files with zero cross-contention against the standards merge trains, so it starts immediately and each item pays independently the moment it merges — a half-done turnaround still ships the collision fixtures, the reactivity contract, and live goldens (graceful degradation under interruption is a design goal, not a hope). T3 completes the device lane after the host-only spine because device work is slow, serial, RAM-heavy, and cannot run in `make ci`. T4 closes the parked/non-overlapping holes last, once the harnesses and gates that give those tests their teeth exist. `tea-fix` rebases onto `audit-fix` HEAD at every wave boundary to absorb merged standards waves; expect and budget for `Makefile`/`ci.yml` conflicts since both engines edit gates.

5. **Wave exit.** `cd learning_tracker && make ci` green (~6.5 min) plus the wave's specific runnable checks; red-demo artifacts attached to the wave journal; human review of the wave summary before the next wave dispatches.
6. **Interruption protocol.** On any crash/kill/rate-limit death: journal-harvest completed worktree commits, then FRESH-RELAUNCH the wave with the remaining items — never resume a killed run.

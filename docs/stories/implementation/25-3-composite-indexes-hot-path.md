# Story 25.3 (DNI-324): Composite Indexes on Hot-Path Queries

Status: review

## Story

As a user opening the dashboard,
I want hot-path queries (dashboard load, scheduler analysis, lifetime aggregation) to be served by composite indexes,
So that startup and dashboard interactions stay under their performance budget (T2.10).

## Acceptance Criteria

1. A composite index `completions_pidx_pid_cur_completed` exists on `completions (profileId, curriculumId, completedAt DESC)`.
2. A composite index on `completions (profileId, sefariaRef, stageId, trackType)` exists. AC originally said UNIQUE "(also satisfies Story 25.2)"; see Dev Notes for why the UNIQUE part has been deferred to DNI-323's new `completion_events` table.
3. An index on `learning_ledger (profileId, createdAt)` exists.
4. An index on `streak_events (profileId, dayUtc, eventType)` exists and is UNIQUE.
5. `EXPLAIN QUERY PLAN` reports `SEARCH ... USING INDEX` (not `SCAN TABLE`) for the three hot-path queries.

## Dev Notes

- **`streak_events` column name.** AR4 specifies `streak_events(profileId, dayUtc, eventType)`. The current `streak_events` table uses `eventTimestamp` (millisecond-precision DateTime). The natural-key UNIQUE column triple is created by Drift's `uniqueKeys` mechanism and lands as `sqlite_autoindex_streak_events_1`. DNI-323 (Story 25.2, in flight in parallel) renames the column to `dayUtc`; that rename will not change the index shape — only the underlying column name.

- **Natural-key UNIQUE on `completions`.** The AC says "also satisfies Story 25.2", but Story 25.2 actually introduces a *new* table `completion_events` that holds the deduped event log. The existing `completions` table is the raw history that backs review-count semantics (one user, multiple completions of the same `(sefariaRef, stageId, trackType)`). Making this UNIQUE breaks ten unrelated tests that legitimately insert multiple rows with the same natural key. DNI-324 therefore creates this composite as a **non-unique index** named `completions_natural_key`; DNI-323 will add the UNIQUE invariant on the new `completion_events` table where it belongs semantically.

- **No `schemaVersion` bump.** Drift's `@TableIndex` is honoured by `createAll()`, and `user_database.dart`'s migration strategy is `onCreate: (m) => m.createAll()` only — no versioned migration history is retained under DNI-322's wipe-install boundary. Adding indexes does not require bumping `schemaVersion`. Verified by inspection (`grep schemaVersion`) and by passing test suite.

- **`build_runner` regeneration.** Required after touching any `@TableIndex` annotation. The worktree was rebuilt with `dart run build_runner build --delete-conflicting-outputs`.

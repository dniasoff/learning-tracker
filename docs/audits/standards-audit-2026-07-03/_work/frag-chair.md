## 1. State of the Codebase

### What this codebase is trying to be

An offline-first, multi-profile Torah-study tracker for children: local Drift databases are the source of truth, Firestore syncs across devices, parents supervise through a PIN-gated mode, and tutors get scoped cross-account access. The development model is unusual and honest about itself: the code is built largely by AI agents in waves, and the standards document's Rule 0 — *a standard ships with its checker* — is the load-bearing idea holding that model together. Judge everything below against that ambition, because the codebase does.

The good news first, and it is genuinely good: the architecture the docs promise is mostly the architecture the code has. `flutter analyze` is clean at zero issues. The 22-check audit passes. EN/HE ARB parity holds at 1,421 keys. Firebase symbols stay confined to their sanctioned modules (Rule 3 holds everywhere but one already-baselined backlog), raw Talker is contained, the single-writer patterns (`CompletionWriter`, `StreakReducer`) are respected at every call site the audit traced, and the append-only ledger design is intact. Of 2,063 audited files, 783 cleared with no findings at all. This is not a codebase in crisis. It is a codebase whose *stated* discipline is real — and whose *enforcement machinery* has quietly rotted underneath it.

### The five systemic problems

**1. The guardrails are broken, and nobody noticed — because the guardrails are how you notice.**
This is the audit's most consequential theme. The nine custom lints enforce nothing anywhere: `dart run custom_lint` crashes outright on the analyzer-9 pin (AUD-guardrails-03), and CI runs it warn-only, so a whole tier of the enforcement stack — layering, RTL geometry, `e.toString()`-in-UI, color literals, raw `logEvent` — has silently been prose for some time. Worse: `make audit` check 15/15, the cross-feature-import gate, is *structurally incapable of firing* — its awk compares a feature name extracted from the file path against a regex match over the whole grep line, which always finds that same file path first; the comparison is self-equal by construction (AUD-guardrails-02, independently discovered by twelve finder batches). It has never caught anything, and real deep imports sailed through it (AUD-tutoring-*, AUD-notifications-*, AUD-scheduler-*). The profileId-in-PK checker silently skips the `Goals` table (AUD-guardrails-01). The custom-lint test suite runs nowhere (AUD-guardrails-17). Committed codegen is stale because the freshness gate is still pending (AUD-core-labels-03). And the error-handler installer that the logging tests pin — `AppLogger.setupFlutterErrorHandlers` — is dead code; production wires its near-duplicate twin inline in `crashlytics_bootstrap.dart`, so the tests verify a path the app never runs (AUD-core-logging-01). For a codebase whose whole development model rests on "agents conform to what fails their loop," a fence that looks solid from the house but has no wire in it is the single most dangerous thing this audit found.

**2. profileId scoping — the product's core invariant — leaks at the edges.**
Multi-profile isolation is not a style rule here; it is the difference between one child's data and their sibling's. The invariant holds in the schema for most tables, and then leaks exactly where the checker doesn't look: `LearningOrderDao` reads and deletes by `curriculumId` alone, so on any household with two profiles sharing a curriculum, one child's custom learning order is served to — and silently deleted by — the other (AUD-core-database-02, a P0 found independently by four batches). Six tables lack the FK+CASCADE that their siblings have, so a tutored-mirror wipe orphans a mirrored child's rows (AUD-core-database-01). `PointsLedger` and `RewardRedemptions` lack `UNIQUE(profileId, ulid)`, so a sync merge can double-credit a child's points (AUD-core-database-03). And `DataExportImportService.importData()` clears sixteen tables *device-wide* before importing one profile's data (AUD-settings-03). None of these are exotic: they are the same defect — scoping enforced by convention instead of by key — appearing wherever the composite-PK rule wasn't mechanically checked.

**3. Child privacy holds at the center and leaks at the seams.**
Beyond the two known, baselined gaps (analytics params, unconditional Crashlytics), the audit found the same class of defect in new places: the outbox dead-letter path ships `entityKey` — literally `profileId:sefariaRef:stage:...` — into Firebase Analytics (AUD-core-analytics-01, P0), and the transactional-email logger writes the full plaintext body, child's name included, through a redactor that only matches on key names it has been told about (AUD-core-email-01, P0). The tutor-invite Cloud Function grants access on an email match without verifying `emailVerified` or the invite token (AUD-firebase-01, P0). The pattern to internalize: PII discipline is enforced at the named choke points and assumed everywhere else — and "everywhere else" is where it fails.

**4. The sync path fails politely and silently.**
The offline-first design is correct on paper and mostly in code, but its failure branches are soft. `ProfileRepositoryImpl` swallows tutor cloud-push failures in a blanket `catch (_) {}` on the assumption that "the outbox will retry" — and for the tutored facade, it won't (AUD-profiles-02, P0). LWW ordering fields are written from the client clock, not `FieldValue.serverTimestamp()` (AUD-core-sync-13), which makes cross-device conflict resolution owner-of-the-fastest-clock. One malformed payload aborts an entire outbox drain (AUD-core-sync-*), a mid-merge crash can strand a stale LWW shadow timestamp (AUD-core-sync-*), and the account-removal path deletes local data without verifying the outbox is drained (AUD-account-01, P0) — for an offline account, that is the user's only copy. Individually these are edge cases; together they describe a sync layer whose happy path is engineered and whose unhappy paths are hoped.

**5. The test suite is wide and soft in the middle.**
TQ-8 is the largest single rule bucket in the register (102 findings): tests that assert what the mock returns, tests pinning stale hand-copied widgets, tests that grep source text instead of exercising behavior, a "regression test" for batch chunking that never calls the chunking code. Forty-seven TQ-6 findings (plus a 377-site deterministic backlog) put wall-clock and real sleeps inside the suite. The user-visible consequence is already in the register: the "Archive (keep history)" flow **wipes** the history it promises to keep, and its test didn't notice (AUD-profiles-01, P0). A suite this size that can't catch that defect is providing coverage, not confidence.

Two smaller currents run through everything: **English leaks into a bilingual app** (21 AX-2 clusters of hardcoded strings and raw `e.toString()` surfaced to Hebrew users — this app's most recurring historical defect class, still recurring), and **the documentation lies in places agents read** (the architecture doc's dependency graph names four features that don't exist and omits two that do, AUD-docs-15; a 993-line superseded standards doc still sits at the repo root contradicting the real one, AUD-docs-04; schema "v14" vs the real v32).

### What to stop doing

1. **Stop adopting rules without checkers.** The register's meta-section lists ~60 rule families with confirmed violations and pending checkers. That backlog *is* the standards debt.
2. **Stop letting agents fork canonical flows.** The profile-delete dialog forked from `deleteProfileFlow` re-introduced a fixed bug (AUD-profiles-*); duplicated `PaceCalculator`/`PinFlowMode` classes drifted (AUD orchestrator AG-4). One definition, one flow, enforced by the AG-4 script.
3. **Stop trusting green tests as evidence.** Verification evidence must exercise the production path (TQ-8); a test of dead code is worse than no test.
4. **Stop treating docs as write-once.** Doc drift misleads the next agent wave; AG-8's pairing rule needs its checker.

The verdict: sound bones, rotten fences. Fix the enforcement machinery first — everything else this audit found is exactly the kind of thing working machinery would have caught.

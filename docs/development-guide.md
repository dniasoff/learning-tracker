# Development Guide — Learning Tracker

> Part of the Learning Tracker project documentation. Start at [index.md](./index.md).
> Generated 2026-05-19 by an exhaustive codebase scan (BMAD `document-project` workflow).

## 1. Prerequisites

| Tool | Version | For |
|---|---|---|
| Flutter SDK | 3.38.6+ | the app |
| Dart SDK | 3.10.8+ | (bundled with Flutter) |
| Android Studio or VS Code | current | IDE + Android toolchain |
| Java | 17 (app build) / 21 (CI rules + build jobs) | Android Gradle |
| Node.js | 20 | Cloud Functions (`functions/`) |
| Node + `firebase-tools` | current | Firestore-rules emulator tests |
| Git | any | — |

Firebase config files (`google-services.json`, `firebase_options.dart`) are **not committed** — they are injected from CI secrets. A local dev build needs them placed manually (`android/app/google-services.json`, `lib/firebase_options.dart`). The app still runs without Firebase — it falls back to local-first mode.

## 2. Installation & first run

```bash
git clone <repo-url>
cd learning-tracker/learning_tracker

flutter pub get
dart run build_runner build --delete-conflicting-outputs   # required — generates Drift/Riverpod/etc.
flutter run
```

`build_runner` is **mandatory** before the first run and after any change to a Drift table, Freezed model, Riverpod `@riverpod` provider, auto_route route, or `json_serializable` model — the app will not compile without the generated `*.g.dart` / `*.freezed.dart` / `*.gr.dart` files.

## 3. Code generation

Generators configured in `build.yaml`: `drift_dev`, `auto_route_generator`, `freezed`, `riverpod_generator`, `json_serializable` (snake-case field rename, explicit `toJson`).

```bash
dart run build_runner build --delete-conflicting-outputs   # one-shot
dart run build_runner watch --delete-conflicting-outputs   # watch mode
```

Localization is generated by `flutter gen-l10n` (driven by `l10n.yaml`; `flutter: generate: true` runs it on build). Source ARB files: `lib/l10n/app_en.arb`, `lib/l10n/app_he.arb` (1538 keys, keep in parity — see `make arb-parity`).

## 4. Running & building

```bash
flutter run                          # debug
flutter build apk --release          # release APK
flutter build appbundle --release    # release AAB (Play Store)
```

`tool/prepare_asset.dart` must run before a release build to convert `assets/db/content.db.xz` → `content.db.gz` (CI does this automatically).

## 5. Testing

The project uses a **story-based acceptance test suite**. Most commands run from the `learning_tracker/` directory.

```bash
# from learning_tracker/
make test-story-6.1        # one story's acceptance tests
make test-epic-25          # all stories in an epic
make test-invariants       # the N1–N8 quality-crisis regression net — RUN THIS after sync changes
make ci                    # analyze + seed validation + full test run

flutter test                       # all unit + widget tests
flutter test --coverage             # with coverage (CI floor: 60% lines)
flutter test integration_test/      # on-device E2E (needs a device/emulator)
```

There are **two Makefiles** with overlapping targets — `learning_tracker/Makefile` (per-story/epic acceptance targets, `test-invariants`, `audit` with 43 greps) and the repo-root `Makefile` (`test-unit`/`test-widget`/`test-integration`, `schema-check`, `arb-parity`, `gen-arch-tables`, `linear-*`). `make help` in either lists its targets. Per `learning_tracker/CLAUDE.md`, story validation is `cd learning_tracker && make test-story-X.Y`.

### Test layout (`learning_tracker/test/`, 851 files)

| Dir | Contents |
|---|---|
| `helpers/` | `inMemoryDb()`, `seedProfile()`, `firestore_fake.dart`, `goldenTest()` (en+he), migration helper. |
| `mocks/` `fixtures/` | `mocktail` doubles (no codegen); content/curriculum/Sefaria fixtures. |
| `core/` `features/` | mirror `lib/` structure. |
| `story_acceptance/` | ~57 files, one per epic; file-level `@Tags(['epic_N'])`, per-group `tags:['story_X_Y']`. |
| `story_acceptance/regression_invariants_test.dart` | the N1–N8 invariant net (see [architecture.md](./architecture.md) §10). |
| `migration/` | per-version Drift migration tests. |
| `integration/` | two-device sync, offline flush, Shabbos suppression, etc. |
| `golden/` | UI snapshot tests + Play Store screenshots. |

**Backlog stories** have a `skip:` on their `group()` with an empty body — activate one by removing `skip:` and filling in assertions. Tests run **real** dependencies (in-memory Drift, real Riverpod/navigation, `fake_cloud_firestore`).

Firestore-rules tests are separate — `functions/test/firestore_rules.test.mjs` (Node's built-in test runner against the Firestore emulator, `firebase emulators:exec --only firestore`, port 8080 per `firebase.json`; run via `make test-rules`). The old `test/firestore-rules/` Jest suite was dead (obsolete `accounts/{uid}` model, non-existent rules path) and was deleted — AUD-t-cross-18.

## 6. Code quality & conventions

```bash
dart format .                       # format (CI: --set-exit-if-changed)
dart analyze --fatal-infos          # static analysis (matches CI)
make audit                          # 43 enforcement greps + custom_lint
make schema-check                   # Drift profileId / composite-index invariants
make arb-parity                     # app_en.arb / app_he.arb key parity
```

`analysis_options.yaml` enables strict language modes and ~80 lints (single quotes, trailing commas, `always_declare_return_types`, etc.).

### The 5 layering rules (custom-lint-enforced)

Defined in `learning_tracker/CLAUDE.md`; rule code in `packages/custom_lints/`. Run `dart run custom_lint`.

1. **No `core/` → `features/` imports.**
2. **No cross-feature deep imports** — only `features/Y/providers.dart` may cross a feature boundary.
3. **Firebase confined** — `firebase_auth`/`cloud_firestore`/`firebase_storage` only in `core/auth/` + `core/sync/`.
4. **Raw `package:talker/talker.dart` confined to `core/logging/`** — log via `AppLogger`.
5. **`.displayNameEn/.displayNameHe` confined to `core/labels/`** — use `CurriculumLabelRenderer`.

`make audit` additionally greps for: no `debugPrint`/bare `print()`, no `DateTime.now()` outside `core/time/` (use `LocalDayClock`), no empty `catch` blocks, no hardcoded RTL-unsafe `EdgeInsets.only(left/right:)`, no `currentAccountId = 1` hardcoding, and more.

### Conventions to follow

- **Dates** — store UTC, display local; never call `DateTime.now()` directly (use `LocalDayClock` / `DateTimeFactory`).
- **Completions** — always write through `CompletionWriter`; never insert `completion_events` directly.
- **Labels** — never read `.displayNameEn/.displayNameHe`; use `CurriculumLabel` / `CurriculumLabelRenderer`.
- **Sync providers** — never `ref.watch` volatile deps into `keepAlive` sync singletons (registers duplicate listeners). See [architecture.md](./architecture.md) §6/§10.
- **Schema changes** — add a Drift migration step, bump `schemaVersion`, add a `test/migration/` test, regenerate.

## 7. Pre-commit hook

Not auto-installed. Enable it:

```bash
# from repo root
make install-hooks
```

It runs `dart format --set-exit-if-changed` + `dart analyze --fatal-infos` (the same checks CI runs).

## 8. Branching & PRs

Branch from `dev`; PRs target `dev`. `make ci` must pass before opening a PR. CI (`ci.yml`) runs format-check, analyze, audit, custom_lint, the full test suite, the 60% coverage floor, Firestore-rules emulator tests, and ARB parity. After touching sync code, also run `make test-invariants`.

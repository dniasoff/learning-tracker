# Development Guide — Learning Tracker

> Part of the Learning Tracker project documentation. Start at [index.md](./index.md).

## 1. Prerequisites

| Tool | Version | For |
|---|---|---|
| Flutter SDK | 3.38.6+ stable (locally verified: 3.44.7) | the app; Flutter bundles Dart |
| Dart SDK | 3.10.8+ | required by `pubspec.yaml` (`environment.sdk: ^3.10.8`; locally verified: 3.12.2) |
| Android Studio or VS Code | current | IDE + Android toolchain |
| Java | 17 (app build) / 21 (CI rules + build jobs) | Android Gradle |
| Node.js | 22 | Cloud Functions (`functions/`) and CI |
| Node + `firebase-tools` | Node 22; `firebase-tools` installed by CI | Firestore-rules and Functions emulator tests |
| Git | any | — |

Firebase config files (`google-services.json`, `firebase_options.dart`) are **not committed** — they are injected from CI secrets. A local build needs them placed manually (`android/app/google-services.json`, `lib/firebase_options.dart`); the live user-data path is Firestore-backed, while bundled content and the device registry remain local.

## 2. Installation & first run

```bash
git clone <repo-url>
cd learning-tracker/learning_tracker

flutter pub get
dart run build_runner build --delete-conflicting-outputs   # required — generates Drift/Riverpod/etc.
flutter run
```

`build_runner` is **mandatory** before the first run and after any change to a Drift table, Freezed model, Riverpod `@riverpod` provider, auto_route route, or `json_serializable` model — the app will not compile without the generated `*.g.dart` / `*.freezed.dart` / `*.gr.dart` files.

## 3. Code generation

Generators configured in `build.yaml`: `drift_dev`, `auto_route_generator`, `freezed`, `riverpod_generator`, `json_serializable` (snake-case field rename, explicit `toJson`).

```bash
dart run build_runner build --delete-conflicting-outputs   # one-shot
dart run build_runner watch --delete-conflicting-outputs   # watch mode
```

Localization is generated by `flutter gen-l10n` (driven by `l10n.yaml`; `flutter: generate: true` runs it on build). Source ARB files: `lib/l10n/app_en.arb`, `lib/l10n/app_he.arb` (1561 user-facing keys, keep in parity — see `make arb-parity`).

## 4. Running & building

```bash
flutter run                          # debug
flutter build apk --release          # release APK
flutter build appbundle --release    # release AAB (Play Store)
```

`tool/prepare_asset.dart` must run before a release build to convert `assets/db/content.db.xz` → `content.db.gz` (CI does this automatically).

## 5. Testing

The project uses a **story-based acceptance test suite**. Most commands run from the `learning_tracker/` directory.

```bash
# from learning_tracker/
make test-story-6.1        # one story's acceptance tests
make test-epic-25          # all stories in an epic
make test-invariants       # the N1–N7 quality-crisis regression net
make ci                    # analyze + seed validation + lint/tests/rules/Functions gates

flutter test                       # all unit + widget tests
flutter test --coverage             # with coverage (CI floor: 60% lines)
flutter test integration_test/      # on-device E2E (needs a device/emulator)
```

There are **two Makefiles** with overlapping targets — `learning_tracker/Makefile` (per-story/epic acceptance targets, `test-invariants`, Firestore/Functions emulator tests, and the active audit checks) and the repo-root `Makefile` (`test-unit`/`test-widget`/`test-integration`, `schema-check`, `arb-parity`, `gen-arch-tables`, `linear-*`). `make help` in either lists its targets. Per `learning_tracker/CLAUDE.md`, story validation is `cd learning_tracker && make test-story-X.Y`.

### Test layout (`learning_tracker/test/`, 929 files)

| Dir | Contents |
|---|---|
| `helpers/` | In-memory content DB (`test_database.dart`), Firestore fakes/fixtures, `goldenTest()` support, clocks, and app/test harnesses. |
| `mocks/` `fixtures/` | `mocktail` doubles (no codegen); content/curriculum/Sefaria fixtures. |
| `core/` `features/` | mirror `lib/` structure. |
| `story_acceptance/` | ~54 Dart files, one or more per epic; file-level `@Tags(['epic_N'])`, per-group `tags:['story_X_Y']`. |
| `story_acceptance/regression_invariants_test.dart` | the N1–N7 invariant net (see [architecture.md](./architecture.md) §10). |
| `data/` | Firestore gateway, repository, and document-ID tests for the live user-data path. |
| `integration/` | two-device sync, offline flush, Shabbos suppression, etc. |
| `helpers/golden_runner.dart`, `goldens/` | Golden-test helper and baseline/probe assets; Play Store screenshots are generated separately under `tool/screenshots/`. |

**Backlog stories** have a `skip:` on their `group()` with an empty body — activate one by removing `skip:` and filling in assertions. Tests run real Riverpod/navigation, the in-memory content Drift database where needed, and `fake_cloud_firestore` for Firestore-backed paths.

Firestore-rules tests are separate — `functions/test/firestore_rules.test.mjs` (Node's built-in test runner against the Firestore emulator, port 8080 per `firebase.json`; run via `make test-rules`, which uses the isolated `demo-rules` project and the rule-coverage gate). The old `test/firestore-rules/` Jest suite is absent.

## 6. Code quality & conventions

```bash
dart format .                       # format (CI: --set-exit-if-changed)
dart analyze --fatal-infos          # static analysis (matches CI)
make audit                          # active repository enforcement checks + lint-rule tests

# from the repository root
make schema-check                   # Drift profileId / composite-index invariants
make arb-parity                     # app_en.arb / app_he.arb key parity
```

`analysis_options.yaml` enables strict language modes and ~80 lints (single quotes, trailing commas, `always_declare_return_types`, etc.).

### The 5 layering rules (defined and unit-tested; standalone custom_lint currently inactive)

Defined in `learning_tracker/CLAUDE.md`; rule code in `packages/custom_lints/`. `make audit` runs the active checks and the custom-lint rule unit tests. The standalone `dart run custom_lint` command is currently a no-op against this project because the analyzer plugin is not discoverable; do not treat a silent run as proof that the app is lint-clean.

1. **No `core/` → `features/` imports.**
2. **No cross-feature deep imports** — only the feature barrel `features/Y/Y.dart` may cross a feature boundary.
3. **Firebase access** — auth gateways live in `core/auth/`; account/session Firebase infrastructure lives in `data/firestore/`; Firestore repositories live in `data/repositories/`; the Storage provider is `core/providers/firebase_providers.dart`. The old `core/sync/` and `features/auth/` paths are absent from the live tree.
4. **Raw `package:talker/talker.dart` confined to `core/logging/`** — log via `AppLogger`.
5. **`.displayNameEn/.displayNameHe` confined to `core/labels/`** — use `CurriculumLabelRenderer`.

`make audit` additionally checks logging, time access, Firebase confinement, RTL-safe layout, account/profile identity, generated-code freshness, test helpers, and other repository invariants; inspect the target for the current complete list.

### Conventions to follow

- **Dates** — store UTC, display local; never call `DateTime.now()` directly (use `LocalDayClock` / `DateTimeFactory`).
- **Completions** — use the Firestore completion repositories/use cases (`FirestoreCompletionRepository` and `CompletionRepository`); the old `CompletionWriter`/`completion_events` Drift user-database path is archived.
- **Labels** — never read `.displayNameEn/.displayNameHe`; use `CurriculumLabel` / `CurriculumLabelRenderer`.
- **Account/Firestore providers** — preserve the account-scoped registry and active-account provider seams in `data/firestore/account_firebase_providers.dart` and `data/firestore/active_account_providers.dart`; dispose account handles on account changes.
- **Schema changes** — content/device-registry Drift changes require the relevant `MigrationStrategy`/`schemaVersion` update in `lib/core/database/`, focused tests under `test/core/providers` or `test/helpers`, and regeneration. Firestore schema changes require the matching repository/rules/index updates and emulator tests.

## 7. Pre-commit hook

Not auto-installed. Enable it:

```bash
# from repo root
make install-hooks
```

It runs `dart format --set-exit-if-changed` + `dart analyze --fatal-infos` (the same checks CI runs).

## 8. Branching & PRs

Branch from `dev`; normal PRs target `dev` (the workflow also accepts `main`). `make ci` must pass before opening a PR. CI (`ci.yml`) runs format-check, analyze, audit, the warn-only custom_lint step, the test/coverage gate, serial tool tests, Firestore-rules tests, Cloud Functions tests, and ARB parity. After touching account/Firestore data paths, also run `make test-invariants` and the relevant repository/rules tests.

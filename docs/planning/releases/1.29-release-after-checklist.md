# 1.29 Release-after checklist (DNI-491)

Story: Linear DNI-491 · bead `learning-tracker-fyh.33` · Epic 1 *One learning record, everywhere*.

This is the release record for the release that follows the AD-49 cutover ([1.28 checklist](1.28-cutover-release-checklist.md)). It removes what is left of the retired stores. The five deny-all `firestore.rules` matches (`completions`, `learning_ledger`, `streak_events`, `bookmarks`, `learning_order`) go. The `streak_events` and `learning_order` indexes go. The retired-symbol allowlist is emptied. `functions/src/deletes.ts` had no entry to remove. AD-13 applies, so there is no data migration. Documents already in the retired collections stay in Firestore, but no client can read or write them, and account or profile deletion removes them with everything else.

## 3. Release run (AC-5)

`deploy-play-store.yml` runs `backend-deploy` after `gate-ci-status`, and the app `deploy` job needs `backend-deploy`. Through `tool/firebase_backend_release.mjs --mode deploy`, the job runs these steps:

1. It lists the deployed functions. It deletes the four retired callables if any is still deployed, then checks that none is left. After 1.28 this is normally a no-op.
2. It runs `firebase deploy --only firestore:rules,firestore:indexes,functions` once.
3. It lists the deployed indexes with `firebase firestore:indexes --json`. A non-interactive deploy never deletes an index that the file no longer declares, so if an index of a retired collection is still deployed, the job runs `firebase deploy --only firestore:indexes --force`. Before that it checks that the prune would delete only retired-collection indexes, or undeclared indexes of collection groups the file declares. If it would delete anything else, the job stops and deletes nothing.
4. It lists the indexes again and fails if an index of a retired collection is still there.
